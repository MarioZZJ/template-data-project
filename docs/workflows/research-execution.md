# 研究执行

## 权威顺序

根 `README.md` 的“研究执行顺序”表是完整命令、输入、输出和依赖关系的权威说明。
`src/` 文件编号只提供视觉顺序，不能替代该表。

单线研究优先使用平铺的三位编号源码，并保留号段用于插入新步骤。
存在多个实质性研究模块时，可以按研究内容分目录；不按抽象编程职责提前搭空骨架。

Titanic [分析阶段](../examples/titanic-walkthrough.md#分析阶段)展示编号源码、数据、实验、正式输出和看板如何协同。

## 每个研究步骤

研究脚本开头记录：

- `Purpose`：本步骤回答的问题。
- `Inputs`：输入路径、数据版本和依赖步骤。
- `Outputs`：生成路径及其正式或可重建属性。
- `Run`：从仓库根目录执行的完整命令。

每个步骤应：

1. 在失败时返回非零状态并给出可定位错误。
2. 固定随机种子或记录随机性来源。
3. 避免覆盖原始数据和未声明的人工产物。
4. 把临时数据写入数据层，把正式图表写入 `outputs/`。
5. 对关键样本量、唯一键、缺失和取值范围做明确检查。

## 运行与更新

- 按 README 表逐项运行，不提供一键运行全部研究的入口。
- 新增、删除或重排步骤时，同步更新 README、`DASHBOARD.md` 和相关实验 README。
- 输出路径或含义变化时同步更新手稿引用和数据来源登记。
- 脚本退出成功只说明该步骤运行完成，不自动等于研究结论成立。

## 重建与验收

正式交付前从 README 第一条适用命令开始逐项重建。
确认正式输出由已登记输入和源码生成，状态文档与实际文件一致，并记录由于权限、成本或环境而未执行的检查。
